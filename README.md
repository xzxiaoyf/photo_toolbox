# 照片，GPS轨迹等操作工具

#### 介绍
这套程序不是先有架构再填功能，而是一个接一个具体的麻烦堆出来的。起点很小：想让手表和手机记录的运动轨迹，跟相机拍的照片对上号。照片本身没带 GPS，但轨迹文件里有——按拍摄时间一匹配，就能给照片补上坐标。坐标补上之后，新的需求立刻跟来了：这些点在地图上是什么样子？积攒几年的照片怎么按时间或地点归置？手机拍的 HEIC 别的软件打不开怎么办？一次拍回几百张鸟图，怎么快速挑出有鸟的照片。

三、十四个子工具
下面按"功能 — 初衷 — 解决的问题"三段式，逐个交代。需要说明的是，多数工具都有一份"相对原版的修复清单"，因为第一版往往能跑通主流程、却在真实素材上暴露问题；下面"解决的问题"一栏写的正是这些被实测抓出来的坑。

3.1 GPS 轨迹写入照片 / 视频
功能。读入 GPX / TCX / FIT 轨迹文件，按每张照片、每段视频的拍摄时间去轨迹里找最近的点，把经纬度（以及能取到的海拔）写进文件的 GPS 字段。支持照片和视频两类载体，带后台线程进度条与可取消，可选取写入前把原文件备份到同目录 exif_backup/。
初衷。这是整套工具的起点。相机不带 GPS，但手机健康 App 和运动手表会完整记录轨迹；两条数据在"时间"这一维上是重合的，对齐之后照片就有了坐标。
解决的问题。核心原则是没匹配上就不写——宁可留空，也不写一个错位置。具体修掉的坑包括：原版依赖 gpxpy，在没装包的机器上启动即弹「缺少 gpxpy」退出，现改为纯标准库自解析；原版正则把 +08:00 整段剥掉只留墙钟时间，实测造成 8 小时误差，现按偏移真换算；小米 TCX 把海拔属性嵌在定位节点内部（不符合 TCX 规范），原版读到 0 个海拔，现两种布局都读；负海拔在新版 exiftool 下会被静默写成正数，现改用字符串写法并总是显式写海拔参考字段；视频时间要按 QuickTime 的 UTC 口径读，写 GPS 则用 Keys:GPSCoordinates。

3.2 高德地图显示拍摄位置
功能。读取单张照片或整个目录的 EXIF，把 WGS-84 坐标转换成高德用的 GCJ-02，在地图上打点，并提供逆地理编码得到的中文地名和照片缩略图；地图上先显示标记点，点击后再显示照片；可一键把目录下所有带 GPS 的照片一次标出并自动适配视野；高德 Key 可在界面配置并持久化到程序同目录的配置文件。
初衷。给照片补上坐标之后，下一个自然的问题就是"这张到底在哪儿拍的"——一串经纬度对人没有意义，落到地图上才有。
解决的问题。原版 import requests 在没装该包的机器上直接崩，现改用标准库 urllib，并为未运行证书安装脚本的 Python 补了证书校验失败的降级链；Key 必须分三个字段保存（JS API Key、JS API 安全密钥、Web 服务 Key），因为新版申请的 JS API Key 必须配合安全密钥，且必须在加载 API 脚本之前设置全局安全配置，用一个 Key 兼两用必然报平台不匹配错误；"显示全部照片位置"原来用无参构造的地图边界对象，实测结果是全世界范围且在扩展后不收敛，等于把视野设成全球而静默失效，现改为加载完标记后调用自适应视野接口；配置文件路径锚定到程序所在目录，避免打包后"Key 存了又丢"。

3.3 轨迹及拍摄位置地图
功能。左边选轨迹文件（GPX / TCX / FIT）、选照片目录，右侧一张内嵌高德地图同时画出轨迹和照片标记：轨迹标出起点（绿）终点（红），显示总里程和起止时间（UTC 与本地两种口径）；照片列表显示文件名、拍摄时间、有无 GPS，点选后显示原始坐标、GCJ-02 坐标、中文地址和缩图；地图上点照片标记也能弹出缩图与地址；另提供"浏览器打开"的网页版。
初衷。3.1 和 3.2 分别解决了"照片有没有坐标"和"单张照片在哪儿"，但一次出行真正想回顾的是走过的路线与沿途拍摄点之间的关系——这是把两者放到同一张图上的理由。
解决的问题。最硬的约束是只用 Python 标准库：不依赖 PIL、requests、tkinterweb，也不依赖轨迹解析第三方库。为做到这点，卫星图和照片缩图所用的 JPEG 解码器是自带的纯 Python 实现，已与 macOS 系统工具逐像素比对验证。此外轨迹时间提供"时间口径"切换（部分设备导出的 Z 常是本地墙钟挂了个 Z），照片的 EXIF 与缩图一律交给外部 exiftool，缩图链按嵌入缩图、原始 JPEG、预览图逐级尝试，都取不到时才用系统工具兜底生成小图。

3.4 Sony 快门数查询
功能。读取索尼照片的相机型号、固件版本、镜头、机身序列号、真实快门数、拍摄时间和 GPS；有 GPS 时转换成 GCJ-02 后调用高德逆地理编码显示中文地址。界面提供「🔑 设置高德Key」按钮，录入后先校验再保存。
初衷。买二手相机时，外观可以修饰，但机身的真实快门数是判断磨损程度最硬的指标——它由相机自己累计写入，改不了。
解决的问题。原版依赖第三方包 pyexiftool，机器上没装就跑不起来，现改为直接调用系统 exiftool 命令行，源码运行和编译分发都不再需要额外装包；高德 Key 外置在同目录的配置文件中（明文保存），"运行 py"与"打包后"都能正确找到。

3.5 相机 EXIF 信息读取（全量诊断）
功能。选择任意照片或视频（jpg、jpeg、arw、png、tif、heic、mp4、mov 等），以格式化 JSON 输出该文件的全部标签——EXIF、MakerNotes、Composite、File 各组都在。读取在后台线程执行，窗口不卡，读取中按钮自动禁用防止重复点击；结果可一键复制或保存为 .json / .txt；状态栏显示标签数量与耗时，底部常驻显示 exiftool 的实际路径。
初衷。这是一个诊断工具，不是日常使用工具。前面那些工具遇到的"海拔读不到""时间差 8 小时""视频 GPS 写不进去"之类问题，最终都是靠把原始标签一条条打出来才定位到根因的。留着它，下次再遇到怪问题就有第一手材料。
解决的问题。原版同样依赖 pyexiftool，没装就跑不起来，现换成命令行调用；结果输出为结构化 JSON 而非纯文本，便于对比与检索。

3.6 GPX 时间修正（UTC+8 转 UTC）
功能。把小米健康 App 导出的 GPX / TCX 里被写错的时间标志改写成真正的 UTC 加 Z，其余数据一律不动。例如本地时间 08:30 被写成 08:30:00Z 的，改成 00:30:00Z。另附可选的输出缩进格式化（小米导出的文件整份首尾相连、常常只有一行），缩进宽度可选 2 空格 / 4 空格 / Tab，也可关闭，关闭后输出与源文件排版完全一致。
初衷。这是整条时间链路的第一道校准。小米导出时把中国区的本地时间直接配上了 UTC 的 Z 后缀——看起来是标准 UTC，实际快 8 小时。这个错误如果不先修掉，后续按时间匹配照片、按时间插值补点的每一个环节都会整体偏移 8 小时。
解决的问题。防重复处理：文件名已带修正标记时弹窗告警并要求二次确认，否则会把修正过的文件再减 8 小时，累计 −16 小时；改 0 处时不再谎报成功，而是明确提示"未发现需要修正的时间标志"并且不生成输出文件；处理前先预览各类修改点的数量与前几条前后对照，让用户确认偏移方向；放弃"正则改文本"改为 XML 树遍历，因为原版正则只认一种紧凑写法，带属性的、内部有换行的、缺秒的、小数位超长的全部漏改；补齐 TCX 的圈属性与活动标识节点，否则同一文件里单圈起点与首个轨迹点差 8 小时；正则跑在原始文本上会连 XML 注释里的时间节点一起改掉，树遍历不会碰注释；改按 XML 声明自动识别编码，GBK 文件不再解码报错。

3.7 GPX / TCX 轨迹插值补全
功能。在相邻两点时间间隔超过阈值（默认 20 秒）的区间里，按等时间线性插入补全点，让轨迹成为逐秒连续的序列。处理前先预览确认，支持命令行只分析不写文件。
初衷。主要用途只有一个：按时间匹配照片、给照片写 GPS。信号差、进隧道、中途暂停都会让轨迹缺采样点，于是照片恰好落进缺口里，匹配不到坐标，前一个工具就"没匹配上不写入"，照片只好留空。
解决的问题。原版 TCX 通路是死的——注册命名空间时必抛异常，任何 TCX 文件点提交都只会弹错误框；改为"原位插入"而不是"删掉整段再重建"，原版会把解析失败的点连同海拔和扩展信息一起静默删除，返回值甚至把删除算成负数；解析失败的点不再被跨过去插值，否则会跨过被删的点凭空伪造一条直线；时间真换算，原版会把已解析出的真实偏移覆盖掉，把带 +08:00 的时间当成 UTC，实测因此插入近三万个伪点；新增最长插值间隔保护（默认 300 秒），超过阈值的缺口跳过并告警，不伪造直线。

3.8 GPX 轨迹方向反转
功能。把 GPX 文件里的轨迹整体反向（从终点走向起点），并保证输出符合 GPX 1.1 对时间字段的硬性要求：一律为 UTC，并以 Z 结尾。多段轨迹会同时倒置段序，得到完整反转。
初衷。轨迹录反了——起点终点颠倒——需要倒过来才能与其他工具的顺序、与照片的时间轴对应上。
解决的问题。原版把时间里的偏移量直接抹掉再补 Z，本该是 8 小时前的时刻被原样保留，凭空谎报 8 小时；现改为真正换算到 UTC 再写 Z，连负偏移也能识别。混合时区（部分带 Z、部分不带）不再抛"不能在有时区与无时区的时间之间做差"的异常；部分轨迹点缺时间字段时不再"点倒序但时间原样保留"（那既不是 UTC 又是倒序），而是照常归一化为 UTC 并在日志里告警；支持带前缀的命名空间写法，原版按空默认命名空间查找会误报"未找到轨迹段"；多段轨迹原版只做段内倒序，结果是 2、1、4、3 而不是完整反转。

3.9 照片按拍摄年月分类
功能。用 exiftool 读元数据，把照片和视频按【年月】或【年月日】两种模式归档到对应目录，支持"跳过已存在文件"，带实时日志区、进度条和"取消处理"按钮。
初衷。好几年拍的照片堆在一个目录里，想按时间线整理出一条脉络，手工建目录再拖拽几千个文件不现实。
解决的问题。日期解析重写，修正紧凑格式的切口错位、全零时间戳造出的垃圾目录、非法的月份数值照算，全部改为严格校验；视频时间改由 exiftool 在读取端换算本地时间，原版把 UTC 值直接当本地时间，跨日跨月的归类全错；扫描时排除目标目录，避免把上次分类的产物再分类一次造成无限增殖；处理函数加顶层异常兜底，不再出现"一个异常就让按钮永久禁用、只能重启"；exiftool 改分批读取（每批 500 个文件、单批 600 秒超时），一批失败不影响其余。

3.10 照片按 GPS 地点 + 日期分类
功能。目录结构为"国家 / 城市 / 年月日"，没有 GPS 的归入"其他 / 年月日"；支持从视频里提取 GPS 坐标并自动校正 UTC 时间；仅中国大陆的坐标转换成 GCJ-02，港澳台及海外保持 WGS-84；带行政区划兜底与反向地理编码重试。
初衷。按日期归档回答的是"什么时候拍的"，但回忆一段旅行往往是"那次去了哪儿"——按地点归档更贴近人对旅行的记忆方式，两者可以并存。
解决的问题。视频时间校正改由 exiftool 在源头完成，删掉了"一律按 UTC 加本机偏移"的错误假设——iPhone 等设备的视频多为本地时间，而用本机时间减 UTC 时间的算法在夏令时区还会再错 1 小时；视频坐标串的经纬序按规范默认"纬度在前、经度在后"，只在该顺序的值域校验失败时才交换，消除赤道和本初子午线附近的误判带；进程内异常兜底与"取消处理"按钮，避免按钮永久禁用；进度条改为按文件字节量加权，大小文件混布时节奏才真实。

3.11 修改照片 EXIF 信息
功能。支持照片和视频的 EXIF 查看与编辑，可改时间、GPS 等字段；保存前自动备份原文件到同级的 exif_backup/ 目录。
初衷。元数据写错了总得有办法改回来——相机时间设错、导入时被改乱、坐标写歪，这些都不是不可挽回的事，前提是有一个不至于把文件改坏的编辑器。
解决的问题。度分秒换算的秒数四舍五入到 60 的进位缺陷（会产生 39 度 59 分 60.0 秒这种非法值）；只读标签组禁止编辑，避免必然失败的写入；视频加 GPS 要同时改写坐标键与 XMP，Apple / QuickTime 才认；保存后要解析 exiftool 的告警文本，"0 files updated"必须视为失败而不是成功；文件类型过滤器切片错位（RAW 格式曾混进视频过滤器）改为列表构建。

3.12 照片 GPS 坐标管理
功能。在地图上管理照片的坐标点：给没有 GPS 的照片手动补坐标，或修正写错的坐标，并可从地图上直接选点写入。
初衷。自动写入解决不了所有情况——有的照片轨迹里确实没有对应点，或者当年根本没记录轨迹。这类照片只能靠人回忆位置再手动补。
解决的问题。地图瓦片改为异步加载（后台线程加占位图、缩放防抖），原版读瓦片会阻塞界面；RAW 缩略图提取改为按嵌入缩图、原始 JPEG、预览图逐个尝试，避免把多个标签的二进制拼成非法图片；地址反查加入请求序号校验，快速切换照片或选点时会丢弃过期结果，不再"串门"；坐标解析保留南纬西经符号，含 S / W 字母时返回负值，参考字段缺失时也不再丢失符号；瓦片缓存改为带容量上限的 LRU（上限 512 张）防止内存无限增长。

3.13 HEIC / HEIF / HIF 转 JPG 批量转换
功能。递归扫描源目录（含子目录），把手机拍的 HEIC / HEIF / HIF 批量转成 JPG，输出目录结构与源保持一致；同名 JPG 已存在时覆盖并在命令行明确记录。
初衷。iPhone 和小米默认用 HEIC 记录，体积小、画质好，但很多软件不认。为了让后续那些依赖常规图像格式的工具和软件能用上这些照片，需要一次成批的格式转换。
解决的问题。EXIF 超过 JPEG 单段附加数据 64KB 上限时（小米和 iPhone 的 HEIC 很常见，实测到 285KB），旧版会让整张照片转换失败、界面却仍提示「操作完成」，属于静默丢数据，现在自动精简 EXIF（保留拍摄时间、相机、曝光、GPS）后转换不再失败；方向问题：手机竖拍时旋转属性写在容器里，旧版只搬运 EXIF 方向标记会转出横倒的图，现在解析容器旋转、把像素摆正，并把输出的方向标记统一为 1，任何看图软件里方向都正确；保留 ICC 色彩配置文件（如 Display P3），颜色不偏；原子写出（先写临时文件再改名），中途退出不会留下半个文件。

3.14 鸟类照片批量识别
功能。在后台线程扫描目录内全部照片，用本地 ONNX 模型做检测加分类，识别结果只输出到控制台不刷屏；命中的照片写入边车 JSON（与照片同名的 .bird.json）并在目录里生成汇总报告；全程本地推理，不上云。
初衷。一次拍回几百张鸟图，人工逐张判断"这张有没有鸟、是什么鸟"非常耗时；而把照片上传到云端识别，一方面涉及隐私，另一方面野外常常没有网络。所以选择了本地模型推理的方案。
解决的问题。整图送进检测网络会被压缩约十倍，导致远距离小目标漏检，为此在整图没有确认鸟时自动做 2×2 重叠分块检测兜底；分类器会把飞行姿态认错种，并且会把荷花、蜻蜓一类非鸟目标判成"亚历山大鹦鹉"之类的外国种，据此引入了两道措施——一是以《中国观鸟年报-中国鸟类名录 10.0》做地域校正，二是把中国无分布的类群列为黑名单；关键设计原则是"是不是鸟"只看原始首位分类分，"是什么鸟"才做地域校正，避免校正反过来把真鸟抹掉；此外 opencv-python 的预编译包不带 HEIF 支持，HIF 加进扩展名也读不出来，现在补了 pillow_heif 解码回退路径。
